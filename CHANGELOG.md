# История версий

Схема номеров описана в README, раздел «Версии».

## 4.0.0 — 2026-10-05

Основная версия сменилась: `refresh_rules` больше не принимает пароль, прежняя
[KNOWLEDGE.md](KNOWLEDGE.md) велела его спрашивать — базу знаний модели заменить.
Свой compose надо привести к новому [docker-compose.yml](docker-compose.yml).

* `refresh_rules` без пароля: человек просит «обнови правила» — модель вызывает.
  Если коммит не сменился, ничего не пересобирается, поэтому лишний вызов
  безвреден. Настройка `REFRESH_PASSWORD` больше не читается.
* Правила забираются по адресу и токену из настроек, а не по сохранённым в клоне
  при первом скачивании. Замена токена или адреса действует сразу, удалять том
  с клоном не нужно. Токен вырезается из текста ошибок — он уходит в чат.
* compose берёт адрес, ветку, подкаталог и период опроса из `.env`. Раньше они
  были прописаны в самом compose, и те же строки в `.env` молча не действовали;
  пароль в compose и в `.env.example` к тому же назывался по-разному.
* «проверялось» — время последней проверки репозитория, а не последней
  пересборки: раньше при неизменных правилах там стояла старая дата.
* Битая папка направления не останавливает обновление остальных: по ней
  остаётся прежняя версия, в поле «внимание» — какая папка и что с ней.
* Опрос по часам и запрос из чата не обращаются к клону одновременно.
* README: раздел «Как выкладывать новые правила» — куда класть папку, как
  обновлять направление, как быть с ветками, как проверить. KNOWLEDGE.md: что
  отвечать, если человек не видит свежих правил.

## 3.0.0 — 2026-10-04

Основная версия сменилась: часть ответов изменилась по смыслу, прежние системную
подсказку и базу знаний надо заменить на [PROMPT.md](PROMPT.md) и
[KNOWLEDGE.md](KNOWLEDGE.md), в знания модели добавить справочник
[BSP_BEHAVIOR.md](BSP_BEHAVIOR.md) — как БСП исполняет правила при обмене через план.

Проверки и сведения о поведении БСП перенесены из
[kd2-rules-mcp](https://github.com/egordoronchenko/kd2-rules-mcp) (MIT); сведения о
ветках выгрузки сверены с кодом БСП 2.3.

* Новый инструмент `check_rules` — проверка правил без конфигураций: алгоритмы и
  правила, которых нет; повтор кода; вторая ветка на тот же объект; части ветки,
  которые обмен через план не исполняет; ветка на объект, который не
  регистрируется; правило, которое ничем не вызывается; объект, уходящий только
  ссылкой; формы поиска, дающие дубли; запись объекта в «после загрузки».
* Разбор видит весь код: обработчик поиска и «после выгрузки в файл»,
  «перед загрузкой» у правил конвертации, все три обработчика реквизита,
  обработчики табличных частей, общие события конвертации (правило
  «Конвертация»). Читаются `get_rule_handler`, ищутся `search_rules`.
* `get_rule_handler`: у реквизита до трёх обработчиков — если их несколько, имя
  обязательно (раньше был один, «ПередВыгрузкой»); `prop` принимает и код
  табличной части.
* `get_conversion_rule`: признаки правила (синхронизация по идентификатору,
  «не замещать», «не создавать, если не найден»…), признаки реквизитов
  («обязательное» — тоже поле поиска), обработчики реквизитов и табличных частей
  списком, замечания проверки.
* `trace_document`: вместо «объект выборки декоративен» — что на деле исполняет
  обмен через план (объект выборки — пусковой тип, произвольный отбор не
  исполняется, работает первая ветка на тип). Без правил регистрации — попадает
  ли объект в очередь по составу плана. Каскады, уходящие только ссылкой,
  отдельно. Реквизит узла с режимом выгрузки у правила регистрации. Общие
  обработчики конвертации, срабатывающие для каждого объекта.
* Отключение группы правил больше не наследуется правилами: БСП его не читает.
  Правило регистрации без признака «валидное» считается отключённым — БСП его не
  загружает.

## 2.1.0 — 2026-09-18

Прежние поля ответов не менялись, добавлены новые. Системную подсказку и базу
знаний стоит обновить: в них появился раздел о сверке с конфигурацией.

* `trace_document`: у каждого вызываемого правила конвертации — где стоит вызов,
  обработчик и номер строки (в той же нумерации, что у чтения и поиска).
  Правило, заданное в свойствах ветки, а не вызовом в коде, так и помечено.
  Для вызовов через общие алгоритмы — обе строки цепочки: где ветка зовёт
  алгоритм и где в алгоритме стоит вызов правила.
* `trace_document`: рядом с процессами ветки — откуда каждая метка: своя у
  ветки или пришла от вызываемого правила, и от какого. Раньше метку чужого
  правила нельзя было отличить от действующей выгрузки ветки.
* `search_rules`: отбор по правилу понимает не только код, но и наименование и
  имя объекта — правило регистрации можно назвать именем документа. Если под
  имя подходит несколько правил, ищется по всем. Правило, которого нет ни в
  одном направлении поиска, теперь даёт ошибку с похожими, а не пустую выдачу.
* [PROMPT.md](PROMPT.md) и [KNOWLEDGE.md](KNOWLEDGE.md): сверка с конфигурациями
  через rlm-tools-bsl — реквизиты приёмника, поля запросов, процедуры общих
  модулей, значения перечислений.

## 2.0.0 — 2026-09-18

Основная версия сменилась: ответ поиска стал другим, и прежнюю системную
подсказку надо заменить на [PROMPT.md](PROMPT.md).

* Новый инструмент `get_rule_handler` — полный текст обработчика страницами, с
  номерами строк и признаком полноты. Читает обработчики правил, общих
  алгоритмов, именованных запросов и отдельных реквизитов правил конвертации.
* Новый инструмент `get_rule_queries` — разбор запросов обработчика: пакет,
  временные таблицы, параметры, какому результату пакета какая переменная
  присвоена. Собранный из кусков текст полным не выдаётся.
* `search_rules`: отборы по виду правила, правилу и обработчику; номер строки у
  каждого попадания; поиск по обработчикам правил регистрации, общим
  алгоритмам, именованным запросам и обработчикам реквизитов.
* `trace_document`: вызовы правил конвертации, спрятанные в общих алгоритмах;
  предупреждение о ветках, где объект выборки декоративен.
* `get_conversion_rule`: код реквизита у строк с обработчиком, имя параметра у
  строк, передающих значение параметром.
* В каждом ответе — версия сервиса.
* Библиотека `fastmcp` ограничена версиями 4.x: на них сервис проверен.
* Системная подсказка [PROMPT.md](PROMPT.md) и база знаний [KNOWLEDGE.md](KNOWLEDGE.md).
